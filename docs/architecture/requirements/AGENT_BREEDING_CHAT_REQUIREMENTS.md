# 聊天式配种 Agent 需求文档

> 版本: v1.1 | 日期: 2026-08-01 | 状态: 草案（补充版）

---

## 1. 背景与目标

当前已具备可用的配种 API（可查询目标帕鲁的父母组合）。本需求希望在聊天场景中提供一个可连续探索的 Agent 体验：

1. 用户提问“手工等级最高的帕鲁怎么配种”时，Agent 自动识别目标并返回该目标帕鲁的父母。
2. 父母帕鲁支持“可点击继续查父母”。
3. 用户可持续点击，直到不再继续。
4. 提供“生成配种路线”按钮（或快捷提示），Agent 基于会话历史生成完整路线图并在会话中展示。

目标是把“单次问答”升级为“可交互追踪 + 一键汇总”的配种探索流程。

项目形态约束（新增）：

- 本能力由两个独立项目实现：
  - Agent 服务项目（编排、状态、路线汇总）
  - 前端项目（聊天 UI、点击交互、路线展示）
- 现有配种 API 作为被依赖的数据服务，由 Agent 服务调用。

---

## 2. 用户故事

### 2.1 核心故事

- 作为用户，我想问“手工等级最高的帕鲁怎么配种”，并直接得到目标帕鲁的父母候选。
- 作为用户，我希望点击任一父母帕鲁后，立即看到该父母的父母候选。
- 作为用户，我希望连续点击多个节点逐步向上追溯，不需要重复输入复杂问题。
- 作为用户，我希望点击“生成配种路线”后，系统能根据当前会话轨迹汇总出清晰的路线图。

### 2.2 边界故事

- 当某个帕鲁无可配种父母（特殊规则/不可配种）时，Agent 明确提示“该节点到此结束”。
- 当出现重复节点（用户反复点击同一帕鲁）时，Agent 应识别并避免死循环展示。
- 当会话中存在多个候选目标时，Agent 应提示用户确认目标或给出多个路线分支。

## 3. 交互需求

### 3.1 入口提问

用户自然语言输入示例：

- “手工等级最高的帕鲁怎么配种”
- “手工最强的是谁，怎么配出来”

Agent 行为：

1. 先解析目标（期望识别为手工最高帕鲁）。
2. 返回目标帕鲁信息与父母列表。
3. 每个父母项都可触发“继续查询该父母的父母”。

#### 3.1.1 目标判定规则（必须明确）

- 对“手工最高”这类查询，默认返回 Top-N（建议 N=3）候选，而不是强行只选一个。
- 若 Top-1 唯一，则直接进入父母查询。
- 若存在并列最高，则先让用户二次确认目标，再进入父母查询。
- 用户未确认时，不触发深层展开。

### 3.2 点击展开

每个父母帕鲁作为可点击实体（按钮/链接/快捷指令）。点击后：

1. Agent 读取被点击帕鲁 ID。
2. 调用后端查询其父母组合。
3. 在当前会话追加一条“该帕鲁的父母结果”。
4. 新结果中的父母继续保持可点击。

#### 3.2.1 点击协议（前后端契约）

统一定义三种交互模式，按优先级降级：

1. 原生按钮点击（首选）
2. 会话内链接点击（次选）
3. 文本指令降级（兜底）：`/expand <pal_id>`

点击事件统一抽象为：

- action: `expand_parent`
- pal_id: 被点击帕鲁 ID
- source_message_id: 触发点击的消息 ID

### 3.3 终止条件

任一条件满足即终止扩展（但会话不强制结束）：

- 用户不再点击。
- 当前节点无父母组合（叶子节点）。
- 达到安全深度上限（防止异常回环，默认建议 8~12 层）。

### 3.4 一键汇总

输入框附近提供：

- 按钮: “生成配种路线”
- 或快捷提示: “输入 /route 生成路线”

触发后 Agent：

1. 从会话历史提取“目标帕鲁 + 点击路径 + 已查到的父母边”。
2. 构建路线图（树或 DAG）。
3. 输出可读版本到会话框（文本树 + 简图）。

#### 3.4.1 路线汇总边界（必须明确）

- MVP 默认仅汇总“用户已探索到的分支”。
- 是否自动补全未点击分支为可选开关（默认关闭）。
- 若开启自动补全，需受深度和节点总量限制（见 5.1）。

## 4. 功能需求（FR）

- FR-1: Agent 必须支持自然语言识别“某工种最高等级帕鲁”。
- FR-2: Agent 必须返回目标帕鲁的父母组合列表。
- FR-3: 父母项必须支持继续查询动作。
- FR-4: Agent 必须支持连续多轮点击探索。
- FR-5: Agent 必须支持“生成配种路线”并基于历史数据汇总。
- FR-6: 对不可配种/无父母节点必须返回明确提示。
- FR-7: 对重复节点必须做去重或循环保护。

---

## 5. 非功能需求（NFR）

- NFR-1: 单次点击查询响应建议 < 1.5s（P95）。
- NFR-2: 会话状态可恢复（至少在当前会话生命周期内稳定）。
- NFR-3: 输出需可读、可追踪，节点命名统一。
- NFR-4: 路线生成结果必须可复现（同一会话上下文重复触发结果一致）。

### 5.1 性能与停止策略（补充）

- 深度上限: 默认 10（可配置 8~12）。
- 节点总量上限: 默认 200（防止图爆炸）。
- 路线生成超时: 默认 8s（超时返回部分结果 + 提示）。
- 重复访问阈值: 同一节点重复展开超过 3 次时提示复用历史结果。

### 5.2 会话恢复策略（补充）

- 会话内恢复: 必须支持（刷新后可恢复当前会话图）。
- 跨会话恢复: 可选（M2 规划）。
- 最低持久化字段: `target_pal`、`explored_nodes`、`edges`、`click_trace`。

---

## 6. 会话状态模型

建议在 Agent 内维护以下状态：

- session_id: 当前会话 ID
- target_pal: 初始目标帕鲁
- explored_nodes: 已查询过的帕鲁集合
- edges: 已发现父母关系边集合
- click_trace: 用户点击轨迹（按时间）
- pending_frontier: 尚未展开但可展开节点

状态更新规则：

1. 首次目标识别后写入 target_pal。
2. 每次点击成功后追加边并写入 click_trace。
3. 若节点已存在于 explored_nodes，则只提示“已查询过”并可复用历史结果。

## 7. 输出格式建议

### 7.1 普通查询输出

- 目标摘要
- 父母列表（每项具备可点击动作）
- 节点状态标签（可继续/叶子/已展开）
- 展示排序规则（默认）:
  - 先按是否可继续展开
  - 再按帕鲁可得性（`is_wild=true` 优先）
  - 最后按名称稳定排序

示例（文本示意）：

- 目标: 阿努比斯（手工 Lv6）
- 父母候选:
  - 棉悠悠 + 捣蛋猫 [点击棉悠悠] [点击捣蛋猫]
  - 雷隐鹿 + 烽歌龙 [点击雷隐鹿] [点击烽歌龙]

### 7.2 路线图输出

建议双格式：

1. 可读树：

```
阿努比斯
├─ 棉悠悠
│  ├─ ...
│  └─ ...
└─ 捣蛋猫
   ├─ ...
   └─ ...
```

2. 结构化数据（供前端渲染）：
- nodes: [{id, name, depth, status}]
- edges: [{source, target, method}]
- roots: [target_pal_id]

### 7.3 错误反馈模板（补充）

- 超时: “查询超时，已保留当前进度。可重试或继续展开其他节点。”
- 无父母: “该帕鲁当前无可用父母组合，已标记为叶子节点。”
- 节点重复: “该节点已查询过，已复用历史结果。”

## 8. API 集成方案

## 8.1 推荐方案（优先复用现有 API）

优先调用已完成的 API：

- `POST /api/query`
  - 用于自然语言入口与工种筛选（如“手工最高”）
- `GET /api/breeding/tree/{pal_id}`
  - 用于点击节点后查询父母
- `GET /api/pal/{pal_id}`
  - 用于节点详情补全（可选）

理由：

- 已有能力成熟，改造成本低。
- 可复用当前 ORM 与业务规则。
- 降低 Agent 与数据层耦合。

### 8.2 可选优化方案

若后续性能或一致性要求更高，可新增聚合接口（例如一次返回多节点父母）。
当前阶段不强制。

## 9. Agent 编排技术选型

### 9.1 首选: LangGraph

推荐原因：

- 天然支持“有状态、多步、可中断恢复”的图式流程。
- 适合“查询 -> 点击 -> 继续查询 -> 汇总”这种循环交互。
- 可以把“生成路线”建模为独立子图，便于扩展。

建议图节点：

- ParseIntentNode: 解析用户意图与目标
- QueryParentsNode: 调用 API 查父母
- RenderClickableNode: 生成可点击结果
- HandleClickNode: 处理点击事件
- SummarizeRouteNode: 生成路线图

### 9.2 备选方案

- 轻量状态机 + 函数路由（实现快，但后续可扩展性弱）
- 纯 ReAct Agent（灵活，但状态显式管理较弱，不适合长链可追溯）

结论：优先 LangGraph。

## 10. 关键流程（逻辑）

### 10.1 首次提问流程

1. 用户输入“手工等级最高的帕鲁怎么配种”。
2. Agent 识别意图：`query_top_suitability_then_breed`。
3. Agent 调用 API 找到目标帕鲁（手工最高）。
4. Agent 查询目标父母并返回可点击父母项。

### 10.2 点击展开流程

1. 用户点击父母帕鲁 A。
2. Agent 读取 `clicked_pal_id=A`。
3. 查询 A 的父母并追加到会话。
4. 更新状态（nodes/edges/click_trace）。

### 10.3 生成路线流程

1. 用户点击“生成配种路线”。
2. Agent 汇总会话图数据。
3. 输出文本树 + 结构化路线结果。

---

## 11. 异常与容错

- API 超时: 提示“查询超时，请重试”，并保留会话状态。
- 节点不存在: 提示“未找到该帕鲁”，允许回退上一步。
- 无父母: 标记叶子节点并提示可改选其他分支。
- 循环风险: 检测已访问节点，避免重复深挖。
- UI 不支持点击: 自动回退到 `/expand <pal_id>` 指令模式。

---

## 12. 可观测性与埋点（补充）

建议最小指标集：

- 首问识别成功率（是否正确识别目标帕鲁）
- 点击展开成功率
- 平均探索深度
- 路线生成成功率
- P95 响应时延（首问/点击/汇总分开统计）
- 错误原因分布（超时/无结果/服务错误）

建议日志关键字段：

- `session_id`, `target_pal`, `action`, `pal_id`, `latency_ms`, `result_count`, `error_code`

## 13. 验收标准

- AC-1: 输入“手工等级最高的帕鲁怎么配种”可返回目标及父母列表。
- AC-2: 父母项可点击并返回下一层父母。
- AC-3: 连续点击 5 轮以上不会丢状态或死循环。
- AC-4: 点击“生成配种路线”可输出完整路线图。
- AC-5: 路线图与会话中已探索到的节点边一致。
- AC-6: 并列最高场景可返回候选并要求用户确认。
- AC-7: 点击不可用时可用 `/expand <pal_id>` 完成同等功能。
- AC-8: 路线生成超时时返回“部分结果 + 明确提示”。

### 13.1 验收样例（固定数据回归）

建议最少 5 条固定用例：

1. `手工等级最高的帕鲁怎么配种`
2. 点击 Top-1 结果中的父母 A
3. 连续展开 5 层
4. 对已展开节点重复点击 2 次
5. 点击“生成配种路线”

每条用例需要定义：

- 输入
- 预期意图
- 预期节点/边增量
- 预期输出关键字段

## 14. 里程碑建议

- M1（MVP）
  - 首次提问 + 点击展开 + 基础路线汇总（文本树）
- M2
  - 增加结构化路线输出（前端图渲染）
- M3
  - 多目标分支管理、会话恢复与性能优化
